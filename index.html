GIT VS GITHUB

Know the difference

⚙️

Git

  • ✓ Version control system (software)
  • ✓ Works locally on your machine
  • ✓ Tracks code changes over time
🌐

GitHub

  • ✓ Web-based hosting platform
  • ✓ Social network for code
  • ✓ Adds collaboration features

Think: Git is the engine, GitHub is the car

COLLABORATION

COLLABORATION WORKFLOW

1. Clone the repo
2. Create a branch (git checkout -b feature-name)
3. Make changes & commit
4. Push branch to GitHub
5. Open a Pull Request
6. Team reviews your code
7. Merge after approval
8. Delete branch, repeat! 🔁

BEST PRACTICES

PULL REQUESTS

Make PRs easy to review:

  • Keep them small (< 400 lines when possible)
  • Clear title describing the change
  • Description explaining why and what
  • Link related issues (#123)
  • Add screenshots if UI changes
  • Request specific reviewers

Good PRs get merged faster!

BEST PRACTICES

CODE REVIEW

When reviewing:

  • Be kind and constructive
  • Ask questions, don't demand
  • Praise good code too!
  • Focus on logic, not style

When receiving feedback:

  • Don't take it personally
  • Ask for clarification
  • Learn from every review
  • Thank reviewers

COMMON MISTAKES TO AVOID

❌ Don't Do This:

  • ❌ Commit sensitive data
  • ❌ Huge commits
  • ❌ Not using .gitignore
  • ❌ Work on main branch
  • ❌ Unclear commit messages
  • ❌ Ignore merge conflicts

✅ Do This Instead:

  • ✓ Use environment variables
  • ✓ Commit often
  • ✓ Create .gitignore first
  • ✓ Use feature branches
  • ✓ Descriptive messages
  • ✓ Resolve conflicts promptly
